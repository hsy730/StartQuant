## 一句话定义

因子代码每次变更都生成一条不可变版本记录，回滚前再自动备份当前版本，历史只增不减。

## 核心要点

- 版本记录固定保存四要素：code、description、change_reason、created_at，缺一不可，否则事后无法判断"为什么改"。
- 版本号自动生成为 `v{major}.{minor}`，`major = count // 10 + 1`、`minor = count % 10`，即 v1.9 之后是 v2.0，版本号只作标识不作语义比较。
- 回滚不是直接覆盖：先调用一次 `create_version` 备份当前代码，变更原因写明"回滚前自动备份"，再恢复目标版本的 code 与 description。
- `is_current` 是单值标记，回滚后由目标版本持有，保证任一时刻只有一个当前版本。
- 版本对比只判断 `code_changed` 与 `description_changed`，不推断影响面。

## 适用场景 / 边界

- 适用：因子代码编辑、回滚、审计、A/B 对比同一因子的两版实现。
- 边界：回滚会新增一条版本，不能删除历史；`auto_increment=False` 时固定写 v1.0，可能出现重复版本号；删除版本属于破坏性操作，需谨慎。
