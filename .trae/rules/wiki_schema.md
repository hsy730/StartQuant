# Wiki 结构规范（LLM 自动维护）

> 适用场景：在对话中即时创建 / 更新项目 `wiki/` 知识库时，必须遵守本规范。
> 设计原则：**页面类型只有三种，章节固定，索引与日志格式不可变**。模型不"设计"结构，只做归类与归位。
> 违反即视为知识库污染。

---

## 一、目录结构（强制）

```
wiki/
├── index.md              ← 内容目录（每次变更后必须更新）
├── log.md                ← 操作日志（只追加，不修改）
├── concepts/             ← 概念页：抽象思想、方法、模式
├── entities/             ← 实体页：具体的人、工具、项目、产品
└── syntheses/            ← 综合页：跨来源的对比、总结、分析
```

**硬规则**：

- 不得在 `concepts/`、`entities/`、`syntheses/` 之外创建页面。
- `index.md` 与 `log.md` 不得被当作知识页面写入正文内容。
- 禁止创建嵌套子目录（如 `concepts/ai/xxx.md`），所有页面平铺在对应类型目录下。

---

## 二、三种页面类型及判定

| 类型 | 目录 | 判断标准 | 示例 |
|------|------|---------|------|
| 概念 | `concepts/` | 可复用的**抽象思想、方法、原则、模式**，不依附于具体事物 | 增量知识编译、外科手术式编辑、NO_CHANGE 判定逻辑 |
| 实体 | `entities/` | 具体的**人物、工具、项目、产品、组织** | llm-wiki 插件、知微、Karpathy |
| 综合 | `syntheses/` | **跨来源的对比、总结、演进脉络**，必须引用 ≥2 个其他 wiki 页面 | 三款 Wiki 维护工具对比、从 RAG 到 LLM-Wiki 的范式迁移 |

**写入前的判定流程**：

1. 新信息描述的是"一个东西本身"还是"一个可迁移的道理"？
2. "东西" → 实体页；"道理" → 概念页。
3. 若在比较两个已有页面、或梳理多个页面的关系 → 综合页。
4. 无法明确归类 → **不创建新页面**，返回 `NO_CHANGE`。

---

## 三、页面最小必备结构

所有页面必须包含以下 YAML frontmatter，**不得省略字段**，无值写 `空` 或 `[]`：

```yaml
---
标题: 页面标题（中文，专有名词保留原文）
类型: 概念 | 实体 | 综合
状态: 草稿 | 稳定
创建: YYYY-MM-DD
更新: YYYY-MM-DD
来源: [来源标识列表]
---
```

### 概念页必备章节（按顺序，无内容写"暂无"）

```
## 一句话定义
（不超过 50 字）

## 核心要点
（2–5 条，每条一句话）

## 适用场景 / 边界
（什么情况下适用，什么情况下不适用）
```

### 实体页必备章节

```
## 是什么
（1–2 句话，说明身份/用途）

## 关键事实
（列表，只写可验证的信息）
```

### 综合页必备章节

```
## 涉及页面
（wikilink 列表，至少 2 个）

## 核心结论
（1–3 条，每条必须可追溯到"涉及页面"中的内容）
```

### 禁止事项

- 禁止添加"更新记录""历史版本""AI 生成说明"等章节。
- 禁止在正文中写入日期（日期只出现在 frontmatter 的"创建/更新"字段）。
- 禁止用二级标题包裹整页的唯一一段话（那是摘要，放 `index.md` 即可）。

---

## 四、索引与日志格式（强制）

### `index.md`（每次页面创建 / 删除后必须同步更新）

```markdown
# 内容目录

## 概念
- [[增量知识编译]] — 一句话摘要
- [[NO_CHANGE 判定]] — 一句话摘要

## 实体
- [[llm-wiki 插件]] — 一句话摘要

## 综合
- [[三款工具对比]] — 一句话摘要
```

规则：每新增一个页面，在对应分类下追加一行；每删除 / 重命名一个页面，移除或修正对应行。**摘要不超过 30 字**。

### `log.md`（只追加，格式固定）

```markdown
## YYYY-MM-DD | 操作类型 | 目标页面
- 变更说明（一行）
```

操作类型仅限：`创建`、`更新`、`删除`、`跳过`（`跳过` 用于记录 `NO_CHANGE` 的原因）。

---

## 五、链接规则

- 页面之间使用 `[[页面标题]]` 双链（Obsidian 风格）。
- **概念页**："核心要点"中提及另一个已存在的概念或实体时，必须加双链。
- **实体页**："关键事实"中提及另一个已存在的实体时，必须加双链。
- **综合页**：必须链接其"涉及页面"中的全部页面。
- 禁止链接不存在的页面：写入双链前必须检查目标是否存在；不存在则先创建目标页，或不加链接。

---

## 六、写入决策树（必须按序执行）

```text
收到用户信息后，按以下顺序判断：

1. 信息是否与 wiki 已有内容相关？
   → 否：返回 NO_CHANGE，不创建页面。

2. 信息是否已在某页面中存在（语义重复）？
   → 是：返回 NO_CHANGE。

3. 信息是否修正了现有页面的错误？
   → 是：定位该页面，仅修改错误部分，更新 frontmatter "更新"日期，追加 log.md。

4. 信息是否属于某个已有页面但尚未记录的新增事实？
   → 是：追加到该页面对应章节，不新增二级标题。

5. 信息是否需要新页面？
   → 按"页面类型判定流程"决定类型。
   → 创建页面，更新 index.md，追加 log.md。
```

**兜底规则（最高优先级）**：如果无法确定归类、或无法定位到已有页面，**优先返回 `NO_CHANGE`，而不是猜测**。这是防止 Wiki 被碎片化页面污染的最有效单条规则。
